# Hermes 契约架构

**状态：** 生效  
**生效日期：** 2026-07-13

本文档定义契约事实所在位置以及必须一起变化的内容。下层可以细化上层，但不能
静默地与上层冲突。

## 契约栈

| 层级 | 权威来源 | 定义内容 |
| --- | --- | --- |
| L0 治理 | `AGENTS.md`、`CONTRIBUTING.md`、`.pb/conventions/` | 贡献和项目不变量 |
| L1 需求 | `.pb/requirements/`、当前迭代需求 | 用户结果、范围和验收 |
| L2 架构 | `.pb/design/`、`docs/design/`、所属模块文档 | 所有权和系统边界 |
| L3 配置 | `hermes_cli/config.py`、示例配置、用户文档 | 支持的设置和优先级 |
| L4 协议 | 工具 Schema、JSON-RPC 方法、适配器接口、API 文档 | 机器消费的契约 |
| L5 体验 | CLI、TUI、Desktop、Gateway、网站文档 | 表面行为和交互 |
| L6 验收 | `tests/`、迭代证据、发布检查 | 契约有效的证明 |

## 变更规则

- 行为变化从 L1 验收标准开始。
- 协议或配置变化必须同步权威定义和同一迭代中的真实消费者。
- 共享核心变化必须提前说明缓存、角色历史、Provider 和同类路径影响。
- 兼容 shim 必须声明移除条件并有集成测试。
- 测试证明关系和可观察行为，不冻结预期会变化的数据。
- 缺陷修复必须指出当前行为失败的精确运行路径。

## 冲突处理

1. 两个权威契约冲突时停止实现。
2. 记录冲突路径和用户可见后果。
3. 先解决更高层的意图。
4. 一起更新所有依赖契约和测试。
5. 在当前迭代 `record.md` 中记录决策。

## 完成门禁

只有范围、实现、测试、文档和迁移/兼容说明一致时，变化才算完成。对于配置、持久化、
安全、远程执行或跨表面协议工作，仅有绿色 mock 单测不算完成。
