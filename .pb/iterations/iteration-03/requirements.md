# 迭代 03 需求：macOS 聊天优先体验

**需求 ID：** CHAT-MAC-003
**状态：** 设计讨论中
**来源：** 用户要求“优化 mac app 目标、更好的聊天能力、去掉不实用的功能、更好的交互体验”
**日期：** 2026-07-15

## 1. 当前问题

当前 App 的技术目标已经完成：SwiftUI 负责宿主、连接、进程、主题和恢复，受控 `WKWebView`
负责完整 Dashboard。问题不在“没有 Chat”，而在聊天没有成为 App 的首要工作流：

1. App 启动后以 Dashboard 根入口为主，聊天用户首先看到的是管理型 WebUI，而不是当前会话。
2. 工具栏把“明快主题”“重新加载”“在浏览器中打开”“设置”并列为高频动作，基础设施动作
   与发送消息、恢复会话的优先级混在一起。
3. 设置窗口把低频的 Dashboard 地址、Hermes 可执行文件路径、自动启动和主题选项全部暴露
   在第一层，增加了聊天用户的认知负担。
4. 连接失败已有重试，但缺少清晰的“回到聊天 / 进入管理中心 / 查看连接详情”的层级。
5. 如果为了改善聊天而在 Swift 中重新实现 transcript、composer 或会话状态，会制造第二套
   聊天事实源，和现有 TUI/Dashboard/Desktop 的行为产生漂移。

## 2. 用户结果

### CHAT-UX-01：快速进入聊天

用户打开 App 后，默认进入当前 Dashboard 的 `/chat`，在连接成功时可以直接继续已有会话，
不需要先穿过管理页面。

### CHAT-UX-02：聊天主路径保持单一事实源

聊天 transcript、composer、流式输出、停止、重试、工具活动、附件和会话恢复继续由现有
Dashboard Chat 提供；Swift 壳只负责窗口、连接、错误和入口层级。

### CHAT-UX-03：失败时能继续工作

离线、Dashboard 启动中、Hermes 缺失或 Web 内容进程终止时，用户能看懂当前状态，能重试，
能进入连接设置或管理中心，不会看到空白窗口或失去已有会话入口。

### CHAT-UX-04：管理能力可达但不干扰聊天

Sessions、Models、Files、Plugins、MCP、Channels、Cron、System 和 Docs 等既有页面不删除，
但从聊天主路径移至明确的“管理中心 / 完整 Dashboard”入口。

### CHAT-UX-05：低频配置分层

基础设置只保留聊天连接所需选项；主题、自动启动、Hermes 路径和浏览器外开等能力作为高级
选项或上下文动作存在，不在聊天工具栏占据同等权重。

## 3. 范围内

- App 默认入口和窗口层级调整为聊天优先。
- SwiftUI 壳层的工具栏、错误状态、重试和管理中心入口重排。
- 基础设置 / 高级设置分层，并为低频动作提供可发现的替代入口。
- 对 `/chat` 深链接、连接恢复、会话继续和返回完整 Dashboard 的可观察契约设计。
- 设计聊天常用键盘操作和焦点行为，但先复用现有 WebUI 能力。
- 设计桌面端可执行的验收场景、回滚方式和兼容门禁。

## 4. 非目标

- 不在 Swift 中重写 Agent Loop、模型调用、工具 Schema、transcript、composer 或会话数据库。
- 不删除 Dashboard 后端已有页面、API、Profile、Session、认证、插件和管理能力。
- 不在本轮引入新的核心工具、JSON-RPC 方法、数据库迁移或新的远程协议。
- 不为了追求“原生”而复制一套与 `apps/desktop`、TUI 或 Dashboard 不一致的聊天状态机。
- 不在本轮处理 iOS/iPadOS、签名、公证、自动更新或正式品牌资产。

## 5. 初步验收口径

| 验收 ID | 可观察行为 | 证据方向 |
| --- | --- | --- |
| CHAT-03-01 | 可从启动状态直接进入真实 `/chat`，不加载静态占位 | Release App + Dashboard 真实连接和页面证据 |
| CHAT-03-02 | 聊天主路径只保留聊天相关动作；管理入口仍可达 | UI 截图 / Rodski 导航场景 |
| CHAT-03-03 | 连接失败、重试、已存在 Dashboard、owned Dashboard 和 Web 内容恢复保持可用 | Swift 行为测试 + Rodski App |
| CHAT-03-04 | 基础设置与高级设置分层，低频设置仍可修改且不改变共享配置 | 设置行为测试 + 配置哈希 |
| CHAT-03-05 | 不产生第二套消息、会话或 Agent 状态 | 源码影响审查 + 真实 Chat PTY |
| CHAT-03-06 | 常用键盘操作和焦点顺序可被桌面用户理解和使用 | UI 场景 / 辅助功能检查 |

## 6. 未决决策

1. “去掉不实用功能”默认解释为从主路径移出并收纳到高级入口；是否允许物理删除 App 内
   的主题切换、浏览器外开和手动 Hermes 路径，需要人类负责人确认。
2. 是否允许 App 默认深链接到 `/chat`，以及“管理中心”是同一 WebView 内导航还是新窗口，
   需要以真实 Dashboard 路由和窗口体验验证后定案。
3. 是否把自动启动保留为默认行为，还是改为只在首次连接失败时提供一次性启动动作，需要
   结合用户的本机 Dashboard 使用习惯决定。
