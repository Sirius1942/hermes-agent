# 迭代 03 记录

## 2026-07-15：启动设计轮

用户目标：优化 macOS App 的聊天目标，去掉不实用的主路径功能，改善交互体验。

## 当前判断

上一轮产品代码和真实验收已经证明完整 Dashboard、Chat PTY、进程所有权、错误恢复和主题
隔离可用。本轮不把“更好的聊天”误解为复制 Agent Core 或重写第二套聊天客户端；先优化
入口、层级、焦点和恢复路径。

## 暂定决策

- 推荐“轻量聊天优先壳”，默认进入真实 Dashboard `/chat`。
- 完整管理功能不删除，移到“管理中心”次级入口。
- 明快主题、浏览器外开、手动 Hermes 路径和自动启动不再占据聊天工具栏。
- 保留现有 WKWebView Chat 作为 transcript、composer、流式输出和会话事实源。
- 暂不增加新的 JSON-RPC、REST、核心工具、数据库或配置迁移。

## 待人类确认

1. “去掉不实用功能”是否按“移出主路径、保留高级入口”执行，还是允许彻底删除某些 App
   入口？
2. 是否接受默认启动到 `/chat`，并把完整 Dashboard 作为“管理中心”？
3. 自动启动是否继续默认为开启，还是改成首次连接失败时的明确操作？
4. 是否需要本轮加入经验证的聊天快捷键；如果 WebView 无法可靠聚焦，则不强行加入。

## 下一步

在上述范围确认后，继续完成 DGL-03-005 设计契约和验收量表，随后形成交互原型契约并交给
TestLoop 做独立设计验收。未经过 TestLoop 设计验收，不进入 DevLoop 实现。

## 2026-07-15：人类批准战略 Pivot

人类负责人明确选择方案 B：原生聊天客户端，并确认以下取舍：

- 低频功能只移出聊天主路径，保留在高级入口，不物理删除。
- App 默认以聊天为核心，完整 Dashboard 作为看板 / 管理中心。
- macOS 自动启动功能继续保留，只迁移到高级设置。
- 后端、功能和数据事实源保持一致，允许不同客户端采用不同界面。
- 新聊天 App 的首个新增平台为 iOS。

该决策属于已批准的战略 pivot。本迭代停止于 DGL-03-004，DGL-03-005 至 DGL-03-009 不再
继续；新的协议、认证和 iOS 工作台设计进入 `iteration-04`，避免覆盖本轮历史。
