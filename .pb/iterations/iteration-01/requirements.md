# 迭代 01 需求

## 问题

仓库拥有完整工程指导，但缺少一个把需求进入、设计、实现证据、独立测试和迭代记录
连接起来的本地操作结构。

## 验收标准

- [x] AC-01：存在开发分支，且没有重写已配置远端。
- [x] AC-02：贡献者拥有统一项目管理入口和简明代码所有权地图。
- [x] AC-03：DevLoop 以 Hermes 专用的九阶段干净队列启动。
- [x] AC-04：TestLoop 以 Hermes 原生测试层级启动，不带入 Darkroom 专属 RodSki 流程。
- [x] AC-05：所有结构验证命令通过，并记录证据。
- [x] AC-06：规划与设计循环覆盖问题定义、备选方案、迭代契约、TestLoop 设计验收交接、
  refine/pivot、预算和 DevLoop 交接。
- [x] AC-07：共享策略只定义规划与设计者、开发者、TestLoop 验收者和人类负责人四类
  职责；关键分数与阻塞项不能被平均成通过。
- [x] AC-08：三个 Loop 驱动和状态控制器通过最终集成验证。
- [x] AC-09：存在中文二次开发架构说明，覆盖官网架构、核心执行链、交付表面、
  扩展决策、配置/Profile、安全、测试和上游同步策略。
- [x] AC-10：二次开发设计讨论已启动，包含候选方向、默认起步方案、待用户决策项和
  DesignLoop 阶段计划。
- [x] AC-11：用户确认第一条真实二开场景、主表面和验收产物后，`DGL-001` 才能完成并
  进入问题定义阶段。

## 约束

- 保留现有用户文件和未跟踪缓存内容。
- 不改变产品代码或安装依赖。
- 在仓库所有者选择 upstream/fork 拓扑前不修改 `origin`。
- 在设计经过 TestLoop 独立验收和人类门禁前不启动 DevLoop 产品实现。
