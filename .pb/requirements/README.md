# 需求索引

项目级意图由 `README.md`、`AGENTS.md` 和 `website/docs/` 下的用户文档定义。本目录
管理需求进入过程，不重复这些权威正文。

## 需求生命周期

1. 记录观察到的问题、用户结果和证据。
2. 确认它是缺陷、刻意边界还是新能力。
3. 识别所有受影响表面和最小 footprint 实现层级。
4. 将接受的范围移入某个迭代的 `requirements.md`。
5. 保持验收标准可观察且不绑定实现方式。

## 必填字段

每条已接受需求必须包含：

- 标识、标题、来源和日期；
- 有复现证据的当前行为；
- 目标行为；
- 受影响用户和表面；
- 验收标准；
- 非目标和兼容约束；
- 安全、隐私、缓存、配置和迁移考虑。

功能需求放在当前迭代；跨迭代决策放在 `.pb/design/` 或 `docs/design/` 下的专门文档。
